# Weather Station

**English** · [Türkçe](README.tr.md)

A device that measures outdoor temperature, humidity and pressure, publishes the readings to the internet over Wi-Fi, and shows them on a browser page.

![Main enclosure and radiation shield](case/sistem_gorunumu.png)

## What we built

### 1. Two boards
| Main board (32x41 mm) | Sensor board (14x16 mm) |
|---|---|
| ![Main board](pcb/main/routed_top.png) | ![Sensor board](pcb/sensor/routed_top.png) |

- **Main board:** ESP32-C3 (Wi-Fi processor module), USB-C, 3.3 V regulator, reset and boot buttons, status LED, and a 4-pin connector for the sensor. Held in the enclosure with two M2 screws.
- **Sensor board:** BME280 (temperature, humidity, pressure) and a connector. It is separate from the main board and connected by a cable, because the processor and regulator warm up and a sensor next to them would read the temperature too high.
- **Design decisions:** The antenna extends past the board edge (the manufacturer's recommendation). Pull-up resistors were added to IO2 and IO8, which set the ESP32-C3's boot mode (found during the datasheet audit). The connector is right-angled, so the cable exits sideways and the enclosure stays low. The first three pins of the connector match the order of common 3-wire sensor modules (VCC, DATA, GND).
- **Tools:** Circuit described in Python with SKiDL and turned into a KiCad schematic ([main board](pcb/main/hava_sematik.pdf), [sensor board](pcb/sensor/hava_sematik.pdf)); each board is built in KiCad from its schematic's netlist, and copper traces are auto-routed with Freerouting. Result: electrical rules check (ERC) 0 errors, design rules check (DRC) 0 violations, schematic and board match.

### 2. Enclosure and radiation shield
- **Main enclosure (37x54x15 mm):** openings for USB-C, the cable exit, the buttons and the LED.
- **Radiation shield (60 mm diameter, 52 mm high):** three conical plates and a roof, so the sun does not heat the sensor while air still flows through. The sensor board hangs from the roof and the cable exits at the bottom.
- Generated by scripts in FreeCAD, with dimensions read directly from the board. A **collision check** was run by intersecting KiCad's per-part 3D board model with the enclosure: no collisions.

### 3. Firmware
C with ESP-IDF. Connects to Wi-Fi, reads the sensor, and publishes the reading as JSON over MQTT (WebSocket + TLS, port 443). The sensor can be the BME280 (main board) or, as an alternative, a DHT22. A BME280 driver, the measurement compensation math, and DHT22 decoding were written.

### 4. Web page
A single-file page (`web/index.html`) that subscribes to the same MQTT topic, shows temperature, humidity and pressure, and displays the weather service's value next to them for comparison.

### 5. How we tested it
- **Datasheet audit (3 rounds):** Pin and circuit details of every part were compared with the datasheets; the issues found (unconnected strapping pins, a missing capacitor) were fixed.
- **Tests on a PC:** The BME280 math was compared with Bosch's datasheet example and the reference formula; the BME280 driver was run against a virtual sensor; DHT22 decoding was tested with datasheet examples.
- **Simulation (Wokwi):** Since the simulator has no BME280, readings were taken with an ESP32-S3 and a virtual DHT22, published over MQTT, and seen on the web page. A negative temperature (−17.9 °C) and about 3 minutes of continuous operation were tested.
- **Process:** The design and code were generated with an LLM (Claude); every step was checked with the tests above, and the issues they found were fixed.
- **Limitation:** Not yet tested on real hardware.
